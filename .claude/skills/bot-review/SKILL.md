# bot-review

ボットの記録を要約し、問題と改善案を短く伝える。

## 手順
1. 要約を出す（引数がなければ paper、5日）。読むのはこの出力だけにする。
   ```bash
   python3 -m bot.review --mode paper --days 5
   ```
2. 次の順で確認し、3〜6行で伝える。
   - 停止やエラーがあったか（あれば最優先で原因を説明する）
   - 損益、勝率、最大DD。バックテストの成績と比べて大きくずれていないか
   - 見送ったシグナルの理由。同じ理由が多い場合は設定の問題かどうか
   - 決済理由の偏り（損切りばかり、など）
3. 改善案は1〜2個に絞り、根拠になる数字を添える。

## 守ること
- **お金に関わる設定（config.toml の [money]、mode、account）は、ユーザーが明示的に頼まない限り変更しない。** 変更案として示すだけにする。
- 数日分の結果だけで戦略を変えない。最低でも20日分、取引30回以上を目安にする。少ない場合は「まだ判断できない」と伝える。
- 原因を調べる必要があるときだけ、`logs/<mode>/events-<日付>.jsonl` を `grep` で絞って読む。ファイル全体は読まない。
- 戦略を変える案は、必ず先に `/jp-backtest` で検証してから提案する。
